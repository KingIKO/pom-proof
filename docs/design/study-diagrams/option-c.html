From the Study page Test shapes

What it is

A test shape is a picture of where a team puts its testing effort. The pyramid has a wide unit base and a narrow end-to-end top. End-to-end tests check a whole flow across the product. The trophy and honeycomb both put integration in the widest part, but they draw the boundary around different code.

How it works

The original pyramid puts service tests between unit tests and user interface tests. The trophy adds static checks, such as type checking, which inspect code without running the app. The honeycomb focuses on a microservice, a small piece of a larger system that other code can use through an interface.

From the Study page Equivalence partitioning and boundary value analysis

Suppose a temperature setting takes whole degrees and accepts 10 through 20, including both ends.

PartitionOne valueExpected result
9 or less5Reject
10 through 2015Accept
21 or more25Reject

In 2-value BVA, use each boundary and the nearest value in the next partition across that edge. The distinct values here are 9, 10, 20 and 21. In 3-value BVA, check each boundary and its closest neighbours on both sides. That adds 8, 11, 19 and 22.

From the Study page Risk-based testing

Combine the ratings in a matrix, a grid with likelihood on one side and impact on the other. The cell where the ratings meet gives the risk level. Run checks for the highest risks first.

For example, suppose a checkout release changes how it handles a slow payment response. If retries are plausible, send the same payment request twice and check that the customer is charged just once. Run that before checking a minor receipt layout change. For a behaviour that must keep working, add an automated check. Google calls this testing habit the Beyoncé rule.

Why it helps

Testing the highest risks first gives the team useful evidence even if time runs out. Other ways to order tests include coverage-based prioritisation, which starts with tests that exercise more code or other targets. Requirements-based prioritisation starts with the requirements stakeholders rank highest.
