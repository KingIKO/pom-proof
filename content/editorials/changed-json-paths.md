## What is going on

A snapshot diff needs the locations that changed. A removed object is a change at one location, even if it used to hold many leaves. A root replacement has the same meaning at the empty pointer, `""`; an empty result means the snapshots agree.

## The fix

1. Start a fresh list and give the visitor separate rules for arrays and plain JSON objects. Prepare a JSON Pointer encoder for object keys.

   **Why:** JavaScript reports `null` as an object with `typeof`, and arrays need their own positional walk. `root-type-change` must report the root even when an array index looks like an object key. Escape `~` first so a tilde generated by the slash escape does not get escaped again in `escaping-and-empty-key`.

   ```js
   const paths = [];
   const isObject = (value) =>
     value !== null && typeof value === 'object' && Array.isArray(value) === false;
   const escape = (key) => key.replaceAll('~', '~0').replaceAll('/', '~1');
   ```

2. Return immediately for strictly equal values. For two arrays visit the index range of the longer array; for two objects visit the union of own keys. Record a missing member or changed leaf once, without descending.

   **Why:** A union sees additions and removals without using object key order. Checking presence before recursing keeps `missing-and-type-change` at `/remove` instead of listing its descendants. The array bound catches the extra element in `array-position-and-extra-item`; strict equality keeps `false` distinct from `0` in `boolean-and-number`. Both inputs serve only as read-only snapshots.

   ```js
   const visit = (a, b, path) => {
     if (a === b) return;
     if (Array.isArray(a) && Array.isArray(b)) {
       for (let i = 0; i < Math.max(a.length, b.length); i++) {
         const next = path + '/' + i;
         if (i >= a.length || i >= b.length) paths.push(next);
         else visit(a[i], b[i], next);
       }
     } else if (isObject(a) && isObject(b)) {
       for (const key of new Set([...Object.keys(a), ...Object.keys(b)])) {
         const next = path + '/' + escape(key);
         if (Object.hasOwn(a, key) && Object.hasOwn(b, key)) visit(a[key], b[key], next);
         else paths.push(next);
       }
     } else paths.push(path);
   };
   ```

3. Visit from `""` and sort the escaped paths by code point, placing a shorter shared prefix first.

   **Why:** The order must come from the pointer text the caller receives. In `code-point-sort`, `U+E000` belongs before `U+10000`. Default JavaScript sort compares UTF-16 code units and reverses those two.

   ```js
   visit(before, after, '');
   return paths.sort((a, b) => {
     const x = Array.from(a, (char) => char.codePointAt(0) ?? 0);
     const y = Array.from(b, (char) => char.codePointAt(0) ?? 0);
     for (let i = 0; i < Math.min(x.length, y.length); i++) {
       if (x[i] !== y[i]) return x[i] - y[i];
     }
     return x.length - y.length;
   });
   ```

## Why the tempting answer fails

Raw keys make a key named `a/b` look like a child under `a`. `escaping-and-empty-key` catches the bad pointers, and `code-point-sort` catches the default sort, even though the decoy walks the right members.

## What the interviewer listens for

Explain the stop rule for a missing subtree and distinguish `[""]` for a root change from `[]` for equality.
