# Decision note: Load question answers on demand

Status: implemented locally. The bank renders summaries before fetching individual answers.

## Problem

With all answers inline, the 294-question bank at `b468be2` contains 2,366,801 bytes of HTML (344,211 bytes gzipped). The individual question pages already carry the full answers for recall and review.

## Decision

The bank renders each card's summary and a no-JavaScript lead and link. Its Astro partial renders the same `AnswerContent.astro` used on the question page, plus the bank's actions. The client fetches the partial when the card opens and keeps the mounted answer for the lifetime of the page. A failed request leaves an Open page link, and reopening retries the fetch.

Search loads `questions/search.json` on the first nonempty query. The index takes prose from Astro's rendered Markdown and skips code blocks and example snippets. Inline identifiers remain searchable as prose. The build uses the Sätteri HTML parser already pinned in Astro's lockfile dependency tree.

## Alternatives considered

Keeping the answers inline avoids an extra request on open but makes every visit download and parse all of them. Sending readers directly to the question page reduces the bank payload but breaks inline comparison and rating.

## Consequences

Opening an answer and searching answer prose each need a request on first use. The initial HTML contains no full answers or highlighted code.

With the same 294 questions, the bank HTML is 382,982 bytes (40,836 gzipped). The index is 492,066 bytes (160,942 gzipped), and a median-sized fragment is 4,431 bytes (1,702 gzipped).

Run `npm run verify` for the project checks, or `npx playwright test tests/e2e/questions.spec.ts tests/ui/a11y.spec.ts` for the focused browser checks. If port 4405 is occupied, change the port through the Playwright config. Setting `BASE_URL` for the entire `verify` command also changes the URLs generated by Astro. Measure the files under `dist/questions/` after `npm run build` with Node's `gzipSync`.
